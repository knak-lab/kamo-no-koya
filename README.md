# カモの小屋 収益分析アプリ

`設計書.md`(実装用最終版)に基づく、GAS(バックエンド)+ React(フロントエンド)の収益分析アプリ。ロジック・UIの元ネタは `アーティファクト.jsx`(kamo-integrated-v21.jsx)、既存のSquare連携スクリプトは `既存GAS.txt`(= `gas/existing-sync.gs`)。

## 構成

- `gas/existing-sync.gs` — 既存のSquare同期スクリプト。**内容は無変更**。`syncFromSquare`(`syncOrders`+`syncCatalog`)が毎日18時に`売上_Square`・`商品マスター`シートを更新し続ける。
- `gas/Sheets.gs` / `gas/CostSnapshot.gs` / `gas/Code.gs` — 今回追加するバックエンド。
- `src/` — Reactフロントエンド(Vite + Tailwind)。

このスプレッドシートには、Square同期シート(`売上_Square`・`商品マスター`)に加えて、**旧AppSheet運用時代からの実データシートが既に存在している**。新アプリはそれらを列名ベースで読み書きし、既存の列・データを壊さないように設計している(想定外の列は空にせずそのまま素通し保存する)。

## シートマッピング(実データシートを採用)

| 概念 | 使用シート | 備考 |
|---|---|---|
| 商品マスタ(原価管理) | `商品マスター_原価管理`(新規) | **id = 商品名**。レシピ・セット内訳・売上_Squareの「商品名」と同じキーで揃えている |
| 材料・包材マスタ | `原材料・資材マスタ`(既存採用) | **id = 材料名**。「単位」列が無かったため新設(既存行は区分から g/包材→個 を初期値に自動セット)。⚠️「区分」の実際の値が「原材料」「包材」である前提で実装しているので、初回動作確認時に必ず確認してください(違っていれば`gas/Sheets.gs`の`RAW`/`PACK`相当の判定・`src/lib/constants.js`の`RAW`/`PACK`定数を実際の文字列に合わせてください) |
| レシピ | `レシピ`(既存採用) | 商品名をキーに、材料・資材1〜20 / 梱包材1〜5 の横持ち形式のまま読み書き。**21件目以降の材料は保存時に切り捨てられる**(元がAppSheetの固定列形式のため) |
| セット内訳 | `セット内訳マスタ`(既存採用) | 区分「構成商品」→component、「梱包・資材」→material としてマッピング |
| 販売先(委託先) | `リベート`(既存採用) | リベート率は「15」のような百分率の数値として保存されている前提(1より大きい値は`/100`して小数化)。1以下ならそのまま小数として扱う |
| 販売形態 | `販売形態`(既存採用・読み取り専用) | 名前一覧のみ。リベート適用可否のフラグが無いため、**「委託先が選ばれていればリベート適用」というルールに変更**(販売形態に関わらず適用) |
| 経費(時間単価) | `経費マスタ_時間単価`(新規) | 人件費は全員共通の単一時給として管理(既存の`店舗利用料`/`人件費`シートは触っていません) |
| 経費 | `経費`(既存採用) | 集計には「日付」列を使用(「対象日付」列は保存はするが集計には使わない) |
| 日次設定 | `日次集計`(既存採用) | 販売先・販売形態は名前で保存(idではなく) |
| 月次目標 / 月次PL予算 / 設定 / Square同期ログ | いずれも新規シート | 実データとの衝突なし |
| TODO | `TODO`(既存採用) | `snoozed`列を新規追加して「ちょっとあと」を永続化 |
| サブタスク | `サブタスク`(既存採用) | `snoozed`列を新規追加。既存の「分類」列は用途不明のため、UIには出さずそのまま保持(読み込んだ値を変更せず書き戻す) |

**このアプリが最初に作った未使用の重複シート**(`材料・包材マスタ` / `販売形態マスタ` / `販売先マスタ` / `セット内訳` があれば)は、上記の実データシートに置き換わったため不要です。空/デフォルト値のみのはずなので、確認のうえ削除して問題ありません。

## GASデプロイ手順

### 初回セットアップ済みの場合(スキーマ変更の反映)

このリポジトリのGASコードは実データシートの構造判明後に大きく書き直されています。既にApps Scriptエディタに古い内容を貼り付けてデプロイ済みの場合は、以下の手順で更新してください。

1. Apps Scriptエディタで `Sheets.gs` / `CostSnapshot.gs` / `Code.gs` の中身を、このリポジトリの最新版で**上書き**する(`existing-sync.gs`に対応するファイルは触らない)。
2. 保存(Ctrl+S)。
3. 関数選択のドロップダウンで `setup` を選び再実行(新規列の追加・トリガー再登録を行う。何度実行しても安全)。
4. デプロイ > デプロイを管理 > 既存デプロイの鉛筆(編集)アイコン → バージョン: 「新バージョン」を選択 → デプロイ。**これをしないと、URLは同じでもコードは古いまま反映されません。**

### 初回セットアップ(未実施の場合)

1. スプレッドシート(既存の収益管理シート、ID: `1qMzUrUaCCI4lTMwQMKVyOeW2F5yDyQEJgqU-B1jAOEY`)を開き、拡張機能 > Apps Script を開く。
2. 既存の `syncFromSquare` 等が入ったスクリプトファイルはそのまま残す。
3. エディタ上部の「+」から新しいスクリプトファイルを3つ追加し、`gas/Sheets.gs` / `gas/CostSnapshot.gs` / `gas/Code.gs` の中身をそれぞれ貼り付ける。
   - 注意: `gas/Sheets.gs`は既存スクリプトと同じ定数名`SPREADSHEET_ID`を避けて`KAMO_SPREADSHEET_ID`という別名を使っています(同じプロジェクト内で同名の`const`を2箇所で宣言するとスクリプト全体が壊れるため)。値は既存スクリプトと同じスプレッドシートIDです。
4. 関数選択のドロップダウンで `setup` を選び、実行する(初回はアクセス許可を求められるので許可)。
   - `stampCostSnapshot`を毎日18:10頃に自動実行するトリガーが登録されます(既存の`syncFromSquare`18:00実行の後に走る想定。触っていません)。
5. (任意)スクリプトプロパティに `API_TOKEN` を設定すると、Web App呼び出し時にトークン一致を要求するようになります(未設定なら誰でもURLを知っていればアクセス可)。
6. デプロイ > 新しいデプロイ > 種類「ウェブアプリ」
   - 実行するユーザー: 自分
   - アクセスできるユーザー: **全員**(「自分のみ」だとフロントから呼べません)
7. 発行されたウェブアプリのURLを控える → フロント側の `.env.local` に設定する。

## フロントエンド

```bash
npm install
cp .env.example .env.local   # VITE_GAS_URL にウェブアプリURLを設定、VITE_API_TOKENは設定した場合のみ
npm run dev
```

- `npm run build` — 本番ビルド(`dist/`)
- `npm run deploy` — `gh-pages -d dist`(GitHub Pagesへデプロイ)

### 保存の仕組み

taskmania/okane-chanと同様、編集可能な全データ(材料・商品・レシピ・経費・TODOなど)を1つのstate木として扱い、変更のたびに800msデバウンスして`saveAll`(全洗い替え)でGASに保存します。`売上_Square`由来の`sales`と`販売形態`は読み取り専用のため保存対象に含まれません。

## 既知の制約・設計判断

- **商品・材料の識別子は名前そのもの**(`id === name`)。既存データ(レシピ・セット内訳マスタ)が商品名・材料名をキーにしているため。改名(鉛筆アイコン/材料名欄)は入力確定時(フォーカスアウト・Enter)にレシピ・セット内訳側の参照も連動して書き換える。売上履歴(`売上_Square`)は過去の商品名のまま残るため、改名後は過去分と新しい名前が別商品として集計される点に注意。
- **客数(伝票数)の算出**: `売上_Square`の1列目`id`は`order.id + "_" + (item.uid || item.name)`という結合文字列。この`id`から最後の`_`区切りを除いた前半を伝票IDとみなして客数を算出している(Square側のIDにアンダースコアが含まれない前提の推定ロジック)。ずれる場合は`gas/Sheets.gs`の`getSales_`を見直してください。
- **Square連携フェーズ2(アプリ→Square Catalog upsert)は未実装**です。マスタタブのトグルはUIとしては存在しますが、「アプリ→Square」に切り替えても実際の書き込みは行われません(設計書のフェーズ9・将来対応)。
- `既存GAS.txt`にはSquare Access Tokenが平文で含まれていたため、git管理下のコピーでは伏字化しています。実際の値はApps Scriptエディタ側のみに存在します。
- レシピの材料は最大20件・梱包材は最大5件まで(既存シートの固定列数に合わせているため)。それを超える分は保存時に切り捨てられます。
